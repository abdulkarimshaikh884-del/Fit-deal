# Fit Deal audit and implementation plan

Scope: inspect the existing app, compare the supplied desktop/mobile references and latest brief, then begin the highest-priority fixes. Preserve Node, vanilla JS, the provider layer and working routes. No deploy or merge in this pass.

## Baseline evidence

- Branch started from `main` with existing uncommitted Home/CSS/generated-page edits. Those edits were backed up outside the repository before changes.
- Baseline: all 29 automated tests pass; provider responses in these tests are mocked. This does not prove real shopping works.
- Local runtime: Gemini credential present (value not inspected), only demo catalog product provider active. Real price results and commission attribution are not verified.
- Browser confirmed Home presents hardcoded prices/discounts, a static countdown, unsupported savings/sizing claims, and Buy links pointing to store homepages.
- Home keyword search filters those static cards; API has no standalone text-search branch. `/find/` shows a missing-results state instead of a search entry page.
- Home saves use invented search ID `deal`, so Saved Buy/Results links cannot resolve.
- Try-On uses a timer and unrelated stock photos, without an AI generation endpoint; this must not be presented as a working feature.
- Product detail/comparison routes do not exist. Profile sizing uses a generic, uncited chart; it is not brand-specific fit evidence.
- Existing protections include upload byte/size checks, store-domain allowlists, CSP, server-side affiliate links and ranking independent of commission. A full security penetration test was not performed.

## Further audit findings to investigate

- `lib/search/match.js`: same brand/style code is accepted without rejecting contradictory colour/variant evidence. Validate variants before claiming equivalent offers.
- `lib/search/normalize.js`: duplicate resolution prefers a priced entry but does not implement the documented freshest-check preference. Numeric extraction also needs explicit currency handling before accepting arbitrary provider price strings.
- `public/js/profile.js`: size estimate comes from a generic inline chart; source-backed brand charts remain required. It must not become a verified fit recommendation.
- `lib/http.js`: proxy trust and forwarded headers depend on deployment topology; review alongside actual Render proxy configuration before treating rate limiting as hardened.
- Photo policy and affiliate membership language elsewhere in supporting pages need owner/provider-account verification. The current Home avoids those unverified membership claims.

**Next milestone:** configure and validate one real product source, then prove screenshot → relevant product with sourced INR price → legitimate retailer product redirect and affiliate tracking. Product detail/comparison pages follow that evidence.
